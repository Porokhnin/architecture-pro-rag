# Исследование моделей и инфраструктуры



## Сравнение LLM-моделей:

| <p align="center">LLM-Модели</p> | <p align="center">Качество ответов</p> | <p align="center">Скорость работы</p> | <p align="center">Стоимость<br>владения и использования</p> | <p align="center">Удобство и простота<br>развёртывания</p> |
|  |  |  |  |  |
| <p align="center"><b>Локальные <br> Hugging Face</b></p> | Зависит от обучения модели. Может и превосходить облачные, в случае хорошего обучения или обучения на "специфических" знаниях | Зависит от объема данных. Очень быстрые ответы на небольшом объеме. | Стоимость владения будет будет рассчитываться из стоимости железа (если будет закупаться отдельное оборудование). Стоимость использования будет рассчитываться из ФОТа специалистов поддерживающие модель | Необходимо будет внедрять и применять практики MLOps, и ModelOps |
| <p align="center"><b>Облачные <br>OpenAI / YandexGPT</b></p> | Точные ответы на общеизвестные темы. Большой набор знаний.  | Приемлемая для большинства задач | Стоимость владения и использования будет зависеть от типа подписки (per token or per mounth). И может быть достаточно высока. | Высокое удобство и простота развертывания, с готовыми пайплайнами и мониторингом.  |

### Облачные модели хороши для быстрого старта, где делается упор на стабильность и качество. <br>
### Локальные модели хороши для проектов с большим объемом запросов и строгими требованиями к конфиденциальности данных.


## Сравнение моделей эмбеддингов:

| <p align="center">Модель эмбеддингов</p> | <p align="center">Скорость создания индекса</p> | <p align="center">Качество поиска</p> | <p align="center">Стоимость <br> владения и использования</p> |
|  |  |  |  |
| <p align="center"><b>Локальные<br>Sentence-Transformers</b></p> | Сильно зависит от железа | Модели вроде E5, BGE-M3 часто занимают первые места в бенчмарке MTEB, обгоняя OpenAI. Гибкость: можно выбрать модель, специально обученную под ваш язык (русский) или домен (код, медицина), либо дообучить (fine-tune) свою. | Сами модели бесплатны. Вы платите за аренду серверов/GPU и зарплату инженерам за настройку и поддержку (MLOps). Выгодно на огромных объемах (миллиарды токенов), где API становится дорогим. |
|  <p align="center"><b>Облачные<br>OpenAI Embeddings</b></p> | Быстрая, но есть сетевая задержка (latency) и Rate Limits (лимиты запросов). | Модели (text-embedding-3-large) хорошо работают «из коробки» для 90% задач, но могут уступать специализированным локальным моделям в специфических доменах или языках, отличных от английского. Fine-tuning ограничен или отсутствует. | Оплата строго за потребление (за 1 млн токенов). Цены сейчас очень низкие (от ~$0.02 за 1M токенов). Выгодно для стартапов и среднего бизнеса: нет затрат на поддержку серверов, GPU и инженерию. |

### Облачные модели хороши для быстрого старта, где делается упор на стабильность и качество. <br>
### Локальные модели хороши для проектов, где необходима гибкость в выборе модели, с большим объемом запросов и строгими требованиями к конфиденциальности данных.


## Сравнение векторных баз ChromaDB и FAISS:
| <p align="center">Векторные базы</p> | <p align="center">Скорость поиска и индексации</p> | <p align="center">Сложность внедрения и поддержки</p> | <p align="center">Удобство в работе</p> | <p align="center">Стоимость владения<br>(учёт инфраструктуры)</p> |
|  |  |  |  |  |
| <p align="center"><b>ChromaDB</b></p> | <p align="center"><b>Умеренная</b></p>Хорошо работает на малых и средних объемах данных (<10-100 млн векторов). Индексация происходит автоматически, но скорость уступает FAISS на больших масштабах. Оптимизирована скорее под удобство, чем под экстремальную производительность.)| <p align="center"><b>Низкая</b></p>Это полноценная векторная база данных «из коробки». Она берет на себя управление хранением, персистентностью (сохранением на диск) и обновлениями данных. Минимум настроек для старта. | <p align="center"><b>Высокое</b></p>Простой API (Python/JS), интеграция с LangChain и LlamaIndex. Установка через pip install. Идеально для быстрого прототипирования и продуктовых решений среднего масштаба. | <p align="center"><b>Низкая</b></p>Open-source (Apache 2.0). Экономит время разработчиков благодаря готовой инфраструктуре. Затраты растут только при необходимости масштабирования на очень большие объемы (требуется больше RAM). |
| <p align="center"><b>FAISS<br>(Facebook AI Similarity Search)</b></p> | <p align="center"><b>Высокая</b></p>«Золотой стандарт» производительности. Поддерживает GPU-ускорение, что делает индексацию и поиск на миллиардах векторов очень быстрыми. Позволяет тонко настраивать типы индексов для баланса между точностью и скоростью. | <p align="center"><b>Высокая</b></p>Это библиотека, а не база данных. Придется самостоятельно писать код для хранения самих данных (векторов и метаданных), сохранения индексов на диск и управления ими. Нет встроенного CRUD (создание/чтение/обновление/удаление) в привычном понимании. | <p align="center"><b>Среднее</b></p>Требует понимания алгоритмов векторного поиска для выбора правильного индекса. Сложнее в установке и интеграции, особенно если требуется поддержка GPU. | <p align="center"><b>Переменная (от низкой до высокой).</b></p>Сама библиотека бесплатна (MIT), но «стоимость владения» включает большие затраты инженерного времени на создание обвязки (API, хранилище, бэкапы). Для высокой скорости может потребоваться дорогое железо (GPU). |


## Рекомендуемая конфигурация сервера
### Я данном этапе необходимо провести пилот на одной группе разработки. По результатам пилота проанализировать результаты и понять насколько мы имеем бизнес профит. После проанализировать нагрузку и определить необходимую конфигурацию железа.
### Текущий пилот можно развернуть и на обычном компьютере: 
#### CPU:	Intel(R) Core(TM) Ultra 9 (2.50 GHz) 28 ядер
#### RAM:	32,0 ГБ
#### GPU:	2,0 ГБ


#### Для выполнения проекта выбрана FAISS в качестве векторного хранилища. Так как FAISS имеет "быстрый вход" и является "золотым стандартом" производительности. Поддерживает GPU-ускорение, что делает индексацию и поиск на миллиардах векторов очень быстрыми. Позволяет тонко настраивать типы индексов для баланса между точностью и скоростью.
